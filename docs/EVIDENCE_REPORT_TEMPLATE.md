# RARPA Evidence Report — PDF Template

**Status:** Implementation reference. Required structure for every evidence report the platform produces.
**Owner:** Joey (compliance lead) — content; engineering — layout.
**Acceptance gate:** Function 14 To-Do 1 (brief).
**Renderer:** Puppeteer + `@sparticuz/chromium` via [`generatePdfFromHtml`](../src/services/pdfGenerator.service.ts). Input is HTML/CSS; output is an A4 PDF.

This document defines the **structure**, **section ordering**, and **HTML/CSS layout** for the consolidated RARPA evidence report. The report is the org admin's single artefact for an Ofsted-equivalent inspection — every claim about a learner's progress, every funding hour, every safeguarding alert must be traceable through these pages.

The template is **structural only**. The data behind each section is assembled by [`buildEvidenceReport`](../src/services/evidenceReport.service.ts) (Function 14 To-Do 2 — separate task); this doc defines the HTML that service produces and the CSS the PDF renderer applies.

Sections appear in the order below. Every section starts on a new page (`page-break-before: always`) except where noted. Page numbers run continuously from the first content page after the cover.

The footer text "Generated by Project Silk for `{org_name}` on `{date}`" is set ONCE in `<div class="page-footer">…</div>` outside any section; Chromium's PDF engine repeats it on every printed page automatically.

The watermark "Project Silk Evidence Report" is rendered as a near-transparent rotated pseudo-element on every page including the cover. It does not interfere with print legibility and is detectable enough to mark a leaked PDF as ours.

## Section ordering — summary

The 11 sections appear in the order listed. The brief mandates this; the rationale is:

1. **Cover** — identity + reporting context
2. **Cohort summary** — headline picture before the detail
3. **Stage 1–5** — narrative of RARPA, in the canonical RARPA order an inspector trained in the framework expects
4. **Teacher oversight** — supplements §02–§07 with the human-attention layer
5. **ILR data summary** — funding-relevant figures, distinct from the qualitative RARPA story
6. **Safeguarding overview** — strictly aggregate; placed after the bulk of the report because an inspector who reaches §10 has already absorbed the cohort context
7. **Methodology appendix** — how to interpret everything above

A future amendment that adds a section MUST land it in this ordering, not at the end — re-ordering after an inspection cycle confuses reviewers comparing year-over-year reports.
